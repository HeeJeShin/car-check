# 중구(car-check) 기획: 2단계부터 커뮤니티까지

2026-10-27 작성. **지금 버전(1단계)은 배포했다고 가정**하고, 다음 버전을 배포하기 전에 필요한 기획과 일정을 정리합니다.
일정은 혼자 퇴근 후·주말에 하는 사이드 프로젝트 기준의 **추정**이고, 1차가 끝날 때마다 다시 잡습니다.

## 서비스가 지향하는 것

> 중고차를 사려는 사람이 **차주들의 실제 경험**을 보고, **매장에서 휴대폰 하나로 "어디서 무엇을 확인해야 하지?"**를 바로 알 수 있는 곳.
> 최종적으로는 차주들이 차 문제점을 이야기하고, 차를 추천하는 **커뮤니티**.

원칙은 1단계와 같습니다. **돈이 걸린 사실 정보(고질병)는 사람이 검증하고, AI는 모으고 정리하고 설명하는 일만 합니다.**
커뮤니티 글도 이 원칙 안에 넣습니다. 글은 자유롭게 쓰되, 고질병 데이터로 올라가는 건 검증을 거친 것만입니다.

## 1단계에 이미 있는 것 (출발점)

| 영역 | 있는 것 |
|---|---|
| 분류 | 제조사 탭(국산 각각, 수입 묶음) + 차 종류 필터(세단·SUV·경차·승합) + 검색(별칭 포함) → 세대·연식 선택 |
| 데이터 | 제조사 6곳·차종 40개·세대 98개, 엔진·미션 조합 224개, 고질병 초안 17건(시드 기준, 초안 → 검토 → 검증/반려) |
| 매장 점검 | 공통 본넷 그림 위 점검 위치 + 시운전 순서 + 체크리스트(브라우저 저장) |
| AI | 무엇부터 알아볼지 안내, 용도별 추천 → DB 차종 연결 |
| 운영 | 관리자 구글 로그인(ADMIN·EDITOR), 변경 이력, E2E·CI, Sentry |

## 1일차: 자동차 기본 분류 화면 구성

지금 분류는 "제조사 → 차 종류"만 있습니다. 사람들은 중고차를 고를 때 **예산·용도·연료**로도 찾기 때문에, 분류 화면을 다시 짭니다. 1일차는 **화면 기획(와이어프레임)과 분류 기준 확정**까지 하고, 구현은 2일차부터 합니다.

**정할 것**
- **분류 기준 우선순위**: 제조사 / 차 종류 / 연료(가솔린·디젤·LPG·하이브리드·전기) / 차급(경형~대형). 모바일 첫 화면에 몇 개를 보여주고 나머지는 "필터 더보기"로 숨길지.
- **국산·수입 나누기**: 지금은 수입을 하나로 묶었는데, 수입 차종이 늘면 브랜드별 탭이 필요한지.
- **연료 필터**: 데이터에는 이미 `Fuel`이 있어 스키마 변경 없이 추가할 수 있습니다. 전기차는 점검 가이드가 다르니(엔진오일 없음) 여기서부터 구분해 주면 좋습니다.
- **차 카드에 무엇을 보여줄지**: 지금은 이름 + 차 종류만 있습니다. 검증된 고질병 수, 대표 이미지(2차 이후) 자리를 미리 잡아둘지.
- **빈 상태**: 검색 결과가 없을 때, 고질병 데이터가 아직 없는 차종일 때 보여줄 문구.

**산출물**: 화면 흐름 1장(분류 → 세대 → 리포트 → 매장 점검), 필터 기준 표, 바뀌는 API 목록.

## 고도화 일정

| 차수 | 기간(추정) | 내용 | 끝났다고 보는 기준 |
|---|---|---|---|
| 1차 | 1주 | 분류 화면 구현 (위 1일차 기획대로) | 연료·차급 필터로 찾은 차가 리포트까지 이어짐, E2E 1개 추가 |
| 2차 | 1~2주 | 엔진룸 이미지 구체화 | 인기 차종 5개에 실제 엔진룸 사진 + 그 차 전용 점검 위치 |
| 3차 | 2주 | AI로 고질병 후보 모으기 (아래 "AI 크롤링 검토" 참고) | 차종 1개에 대해 출처 링크가 달린 초안이 자동으로 쌓이고, 관리 화면에서 검증 |
| 4차 | 3~4주 | 커뮤니티: 차종별 게시판, 고질병 제보 | 일반 사용자 로그인, 글·댓글, 신고, 제보 → 고질병 초안 연결 |
| 5차 | 2주 | 추천 고도화 | AI 추천에 커뮤니티 평가(차주 만족도·문제 제보 수)를 근거로 붙임 |

### 2차: 엔진룸 이미지 구체화
- 지금은 **모든 차가 본넷 그림 하나**를 같이 쓰고, 점검 위치만 %로 찍습니다. 차마다 엔진룸 배치가 달라 실제 매장에서는 위치가 안 맞을 수 있습니다.
- **차종(또는 엔진)별 실제 엔진룸 사진**을 올리고, 그 사진 위에 점검 위치를 찍게 합니다. 사진이 없는 차는 지금처럼 공통 그림을 씁니다.
- 필요한 것: `CarModel`이나 `Powertrain`에 이미지 연결, 이미지 저장소(Vercel Blob·S3 등), 관리 화면에서 사진 올리고 점 찍기.
- **사진 출처가 가장 중요합니다.** 인터넷 사진을 그대로 쓰면 저작권 문제가 생깁니다. 직접 찍은 사진, 허락받은 사진, 제조사 공식 자료처럼 쓸 수 있는 것만 씁니다.
- 직접 찍은 더 뉴 스포티지R 본넷 사진(`web/public/`)이 첫 후보입니다.

### 3차: AI 고질병 수집 → 사람이 검증
고질병 정보는 유튜브와 네이버 카페에 **차주별 경험담으로 흩어져** 있습니다. 이걸 AI로 모아 **초안**까지 만들고, 검증은 지금 있는 심사 흐름에 맡깁니다.

```
공식 API로 글·영상 찾기 → Gemini가 "차종·연식·증상·부위·출처" 추출 → 고질병 초안(DRAFT, 출처 URL 포함)
→ 관리 화면에서 검토 요청 → 관리자 승인(검증됨) / 반려
```
- 같은 증상이 여러 출처에서 나오면 묶어서 "제보 N건"으로 보여주면 신뢰도 판단에 도움이 됩니다.
- 수집은 배치 작업이라, 1단계 문서에서 미뤄둔 큐(BullMQ + Redis)를 여기서 넣는 게 자연스럽습니다.

### 4차: 커뮤니티
- **차종별 게시판**: 세대·연식으로 글을 묶습니다. "올 뉴 투싼 2017 디젤 차주" 같은 맥락이 붙어야 의미가 있습니다.
- **고질병 제보**: 글에서 "이건 고질병 같아요"를 누르면 고질병 초안으로 넘어가고, 같은 심사 흐름을 탑니다. 커뮤니티와 검증 데이터가 여기서 이어집니다.
- **필요한 것**: 일반 사용자 로그인(지금은 관리자만 있음), 역할에 `USER` 추가, 신고·숨김, 도배 방지(지금 있는 요청 제한 재사용), 개인정보처리방침.
- 운영 부담이 가장 큰 단계입니다. 글이 없으면 빈 게시판이 오히려 신뢰를 깎으니, **3차에서 모은 데이터로 리포트가 충분히 찬 뒤**에 엽니다.

### 5차: 차 추천
- 지금 추천은 AI가 용도·예산을 듣고 차종을 고른 뒤 DB 링크를 붙이는 방식입니다.
- 커뮤니티가 생기면 **차주 평가와 문제 제보 수를 추천 근거로** 붙입니다. 계산(점수·순위)은 코드가 하고, AI는 결과를 쉬운 말로 설명만 합니다.

## AI로 고질병 정보를 크롤링할 수 있나? (검토)

**결론: "AI가 직접 긁어오기"는 안 되고, "공식 API로 찾고 AI가 정리"는 됩니다.**

| 출처 | 가능한 방법 | 막히는 점 |
|---|---|---|
| 유튜브 | YouTube Data API로 영상 검색, 제목·설명·댓글 읽기 | 하루 사용량 한도가 있음. 자막은 영상 주인 권한이 있어야 공식으로 받을 수 있음 |
| 네이버 카페 | 네이버 검색 API(카페글)로 제목·요약·링크 가져오기 | 본문은 대부분 회원 전용이라 가져올 수 없음. 로그인해서 긁는 건 이용약관 위반 |
| 일반 웹(블로그·기사) | 검색 API + robots.txt를 지키는 수집 | 사이트마다 허용 범위가 다름 |

- **저장하는 건 요약과 출처 링크만** 둡니다. 원문을 그대로 복사해 두면 저작권 문제가 됩니다. 사용자는 링크를 눌러 원문을 봅니다.
- AI는 그럴듯한 증상을 지어낼 수 있으므로, AI가 만든 건 **항상 초안**이고 출처 URL이 없으면 승인할 수 없습니다(이미 서버 규칙으로 막혀 있음).
- 비용: Gemini 무료 등급 한도 안에서 하루 처리량을 정하고, 이미 처리한 출처는 다시 보내지 않습니다.

## 배포 전에 결정할 것
- 1차(분류 화면)만 먼저 배포할지, 2차(엔진룸 사진)까지 묶을지
- 사진 저장소를 어디로 할지 (무료 범위)
- 4차 커뮤니티를 열기 전 일반 사용자 로그인 방식 (구글만? 카카오 추가?)
